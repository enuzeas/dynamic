## 4. 다음 캡스톤 기술 배분 (앞으로 6회)
| 회차 | 작업 | 도달 상태 |
|---|---|---|
| 다음 캡스톤 | 영상 → 2D 포즈(MediaPipe) + 데이터 수집 **+ 스타일 전이 spike①(아래)** | 영상에서 포즈가 추출된다 |
| 그 다음 | 2D → 3D 모션(SMPL-X) **+ 스타일 전이 spike②** | 포즈가 3D 모션이 된다 + **스타일 전이가 되는지 답이 나온다** |
| 3회차 | 리타겟팅(SMPL → Mixamo) | 모션이 캐릭터에 입혀진다 |
| 4회차 | 렌더/뷰어(three.js) | 웹에서 before/after를 본다 |
| 5회차 | style 추출·주입(Motion Puzzle) — 우리 데이터로 | 같은 동작이 사람마다 다른 결로 움직인다 |
| 6회차 | 평가(DTW, ICC) + 플랫폼 통합 | 완성 데모 |

**스타일 전이 spike (1~2회차 병행, 버려도 되는 실험):** 프로젝트 최대 불확실성은 "스타일이 실제로 눈에 띄게, 사람별로 구분되게 뽑히는가"인데 로드맵상 5회차에 있다 — 앞 4회를 배관에 쓰고 5회차에 실패하면 4주가 날아간다. 그래서 우리 데이터 말고 **이미 깨끗한 공개 모캡(AMASS·Mixamo)에 Motion Puzzle을 그대로 돌려** "출력이 스타일별로 다르게 나오나"만 1~2회차 안에 확인한다. 성공하면 5회차는 "우리 데이터로 재현"이 되고, 실패하면 4주를 아끼고 방향을 고칠 수 있다.

## 4-1. 방향 논의 반영 (2026-07-12)

**카이스트 교수 상담 — 질문 3개 (판단이 필요한 지점만):**
1. 단안 RGB(MediaPipe/WHAM)로 스타일 캡처가 깨짐(footskate) 없이 나오는 게 현실적인가, 멀티캠이 사실상 필수인가?
2. Motion Puzzle(AdaIN) vs 사전학습 diffusion — 캡스톤 6회 안에 데모까지 가기엔 뭐가 맞나?
3. 우리 데이터(직접 촬영 몇 명 × 여러 동작)로 충분한가 — 최소 몇 분/몇 명?

**성공 기준 (소박하게 고정):** "A스타일 출력이 A 원본에 붙고 B스타일과 벌어진다(DTW) + 웹 뷰어에서 눈으로 확인." 미세 뉘앙스가 아니라 **큰 패턴(리듬·보폭·무게중심)** 수준 — 단안 tier가 실제 줄 수 있는 전부.

**실패 시 대비:** 생성 출력이 깨져도 이미 있는 DTW 분석 자산으로 "생성은 아직이지만 스타일이 측정 가능하게 사람별로 다르다"는 분석 데모로 전환 — 빈손으로 끝나지 않는다.

**스코프 가드:** 캡스톤 코어는 **"스타일 전이가 웹 뷰어에서 사람별로 보인다" 하나.** 플랫폼·디지털트윈·광고영상은 발표용 포장(기획·마케팅·콘텐츠 영역)이며 기술개발 시간을 먹지 않는다.

**1인 개발 병목 완화 (기술 8개 중 6개가 박세준 단독):**
- 렌더/뷰어(three.js)는 실제로 송필순이 주도(박세준은 모션 데이터 포맷만 넘김).
- 전 구간 사전학습·오픈소스만 사용, 처음부터 학습 금지 — 모델을 만드는 게 아니라 붙인다.
- 데이터 수집·평가는 전원 유지(크리티컬 패스에서 분리).
