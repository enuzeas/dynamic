# BIO-IP 구현 범위

---

## MVP — 3개월 · 명제 검증

캡스톤 발표에서 방어 가능한 최소 범위. 이것만 나오면 핵심 명제(층위 1) 방어 가능.

### 데이터

- 피험자 8–12명, 동작 2–3종, 인당 5회 반복
- 같은 안무를 각자 따로 촬영 (오클루전 없음)
- 스마트폰 단안 카메라, 정면·충분한 간격·조명 통제

### 파이프라인

- MediaPipe Pose → 관절 좌표 시계열 (오프라인 추출, 실시간 불필요)
- 속도·가속도·저크 특징 계산 (주요 관절 6–8개, 평활화 후 미분)
- DTW 유사도 + 단순 분류기 (1-NN DTW 또는 SVM — 신경망 불필요)

### 검증 출력

- **고유성**: rank-1 accuracy, EER (between-subject 분류 정확도)
- **항상성**: ICC (동일인 세션 간 특징 일관성)
- Jupyter Notebook + 결과 시각화 — UI 없음, 숫자와 그래프만

---

## 5개월 전체 범위 — MVP + 3개 추가

MVP 숫자가 나온 다음에 올릴 층위. 순서 역전 금지.

### 층위 2 — 외형 독립성 검증

- 얼굴 블러 + 음성 스트립 후 동일 파이프라인 재실행
- 식별 정확도가 유지되면 층위 2 명제 성립 ("외형 없이도 식별된다")

### 군무 항상성 테스트

- 솔로 등록 → 같은 안무 군무 영상에서 매칭
- 콘텐츠 완전 통제 조건에서 항상성 강도 검증
- 간격 충분한 군무로 시작 (오클루전 최소화), 다인 트래킹은 다음 단계

### 챌린지 UI 프로토타입

- 영상 업로드 → 다이내믹스 서명 추출 결과 표시 (웹 프로토타입, Flask / 간단한 JS)
- BIO-IP 등록 Mock: 특징점 → 로컬 DB 저장·조회 (블록체인 아님)

### 온디바이스 가능성 확인

- MediaPipe on Mobile 실행 테스트
- 최적화 불필요 — "돌아가는가"만 확인

## 두 범위 모두에서 잘라낼 것

| 항목 | 이유 |
|---|---|
| 블록체인 등록 | 삭제권 충돌 미해결. 법률 자문 전 구현 불가. 로컬 DB로 대체. |
| 프로덕션 모바일 앱 | 스토어 배포 = 법적 검토 필요. 웹 프로토타입으로 충분. |
| 피험자 50명 이상 대규모 수집 | IRB 절차 5개월 내 완료 불확실. 12–15명으로 지표 산출 가능. |
| Layer 3 — CG·애니·로봇 이식 | Layer 1 미검증 상태에서 의미 없음. 후속 과제로 명시 분리. |
| 온디바이스 ML 최적화 (TFLite 등) | TFLite 변환·튜닝은 별도 공수. 서버 사이드 실행으로 대체. |
| 다인 오클루전 트래킹 | re-ID 파이프라인 안정화 없이 군무 전체 추적은 노이즈만 생성. |

## 월별 체크포인트

| 월 | 작업 | 출력 |
|---|---|---|
| 6월 | 데이터 수집 + 파이프라인 구축 | MediaPipe 추출 완료, 특징 계산 스크립트 |
| 7월 | DTW + 분류기 구현 | 유사도 행렬 생성, 초기 정확도 측정 |
| **8월** | **MVP 완성 · 명제 검증** | **rank-1 / EER / ICC 숫자 확정** |
| 9월 | 층위 2 + 군무 테스트 | 외형 제거 후 정확도, 솔로→군무 매칭 결과 |
| 10월 | UI 프로토 + BIO-IP Mock | 챌린지 웹 데모, 등록 Mock 완성 |
| 11월 | 최종 발표 준비 + 문서화 | 발표 자료, 결과 보고서, 코드 정리 |

> **3개월 MVP가 통과 기준이다.** rank-1 accuracy, EER, ICC — 이 세 숫자가 나오면 핵심 명제(층위 1)가 서고 발표 방어가 가능하다. UI보다 숫자가 먼저다.
