# T4 2대 스타일 추출 소요 시간 추정 (2026-08-01)

> 목적 한 줄: **"영상 → 스타일 추출"이 T4 2대로 얼마나 걸리는지** 지금까지 실측·문헌 근거로 추정한다. 성격 표시: 이 문서는 측정 결과가 아니라 **추정치**다 — 파이프라인 절반은 실측(9초), 절반은 미실측(영상→BVH 단계)이라 둘을 섞어 쓰지 말 것.

---

## 1. 파이프라인 단계

```
영상 → [ViTPose 2D + YOLO + DPVO 전처리] → GVHMR + FootMR → hmr4d_to_npz.py
     → retarget_smpl_to_cmu.py → Motion Puzzle(스타일 전이) → CMU→Mixamo → three.js
```

"스타일 추출"이라고 부르는 지점은 실제로는 두 군데로 나뉜다 — 영상에서 3D 모션을 뽑는 앞부분(GVHMR+FootMR)과, 그 모션에서 스타일을 분리·전이하는 뒷부분(Motion Puzzle). 시간이 걸리는 곳도 이 둘이 완전히 다르다.

---

## 2. 단계별 소요 시간

| 단계 | 시간 | 실측 여부 | 근거 |
|---|---|---|---|
| 영상 → 2D/3D 포즈(GVHMR+FootMR) | **미실측** | ✗ | `samsam_plan.md` 76행 — GVHMR **핵심망만** 0.28초/시퀀스. YOLO 검출·ViTPose 2D·DPVO 전처리는 별도 시간, 이 프로젝트에서 합산 실측 없음 |
| hmr4d_to_npz.py + retarget_smpl_to_cmu.py | 사실상 0초 | 순수 배열 변환(CPU) | 코드 확인 — GPU 불필요 |
| Motion Puzzle 스타일 전이 | **~9초/쌍** | ✓ 실측 | `samsam_dev_spec.md` 89행, `style_transfer_server.py`(300초 타임아웃 설정) |

**미실측 구간의 참고치**: GVHMR/FootMR류 파이프라인은 통상 2D 검출+시각 오도메트리(DPVO)까지 합치면 영상 길이의 1~3배 정도 걸리는 경우가 흔하다. 다만 이건 일반적인 경향이지 이 프로젝트에서 잰 숫자가 아니다 — 확답 불가.

---

## 3. T4 2대의 효과

GVHMR·FootMR·Motion Puzzle 전부 **단일 GPU 추론** 코드다. 즉:

| 시나리오 | 효과 |
|---|---|
| 영상 1개를 GPU 2대로 처리 | **효과 없음** — 코드가 GPU 간 분산을 안 함 |
| 영상 N개를 GPU당 1개씩 동시 처리 | **총 처리 시간 절반** — 처리량(throughput)만 늘어남 |

→ "촬영 인원 8~12명 × 8동작"(`samsam_shooting_guide.md`) 규모라면 영상 개수가 80~100개대라 후자 시나리오가 실전에 맞다.

---

## 4. 아직 모르는 것

- 영상 → BVH(GVHMR+FootMR) 전체 파이프라인의 실제 wall-clock — 표 2행이 확정되기 전엔 총 소요 시간을 자신 있게 말할 수 없음.
- Colab T4가 무료 티어라 세션 중 GPU가 배정 안 되거나 끊기는 변동성 — 이 문서의 추정과 무관하게 실전 변수.
