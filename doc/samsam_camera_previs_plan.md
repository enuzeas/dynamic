# 카메라 프리비즈 → AI 영상 생성 스파이크 계획 (2026-07-22)

> 목적 한 줄: 스타일 입힌 스켈레톤에 카메라 각도를 얹어 영상으로 뽑고, 그걸 포즈 기반 AI 영상 생성 모델에 넣었을 때 카메라 앵글이 실제로 결과물에 반영되는지 확인한다.
> **세션 1-6 코어(스타일 전이 자체)와는 별개의 곁가지 스파이크** — 통과해도 캡스톤 코어 스코프에 자동 편입되지 않음, 결과 보고 팀이 편입 여부를 따로 정한다.

## 0. 전제 (기존 3원칙 그대로 상속)
1. 이것도 조립이다 — 사전학습 공개 코드만 쓴다, 처음부터 학습 금지.
2. 실패해도 코어에 영향 없음 — "버려도 되는 실험".
3. 성공 기준은 육안 확인 하나: 카메라 각도만 다르게 넣은 두 구동 영상이, 최종 생성 결과에서도 다른 앵글로 보이는가.

## 2. 모델 후보 비교 (2026-07-23 조사 완료, 실제 repo·README·LICENSE 직접 확인)

| 모델 | 코드/가중치 | 라이선스 | 입력 포즈 포맷 | Colab T4 가능성 | 극단적 카메라 각도 리스크 |
|---|---|---|---|---|---|
| **MimicMotion** (Tencent, ICML 2025) | 있음, HF 체크포인트 | Apache-2.0 | DWPose(COCO-WholeBody 133kpt), RGB 구동영상 내부 검출 | 해상도/프레임 낮추면 경계선 가능 | 정면~반신 위주 데모, confidence-aware guidance로 일부 완충 |
| **Champ** (Fudan/NJU/Alibaba, ECCV 2024) | 있음(학습코드 포함) | MIT | DWPose+**SMPL 기반** depth/normal/semantic 4종 | 어려움(24GB급 GPU 기준) | 이론상 각도 반영 최고(SMPL 메시 기반)지만 **스켈레톤만 있는 우리 렌더로는 depth/normal 자체를 못 만듦** — 조립 범위 벗어남 |
| **AnimateAnyone** (원본) | **코드 없음**(2023-11부터 미공개 유지) | 명시돼 있으나 무의미 | 검증 불가 | 해당 없음 | 선택지 아님 |
| **Moore-AnimateAnyone** (오픈 재현) | 있음 | Apache-2.0 | DWPose | 16GB 경계선 | README가 스스로 "스케일/자세 불일치 시 결과 저하" 인정 |
| **MusePose** (TMElyralab) | 있음, ComfyUI 래퍼 있음 | MIT | DWPose + 자체 pose-align 도구(스케일 불일치 완화) | **512×512×48프레임=16GB 문서화, 4개 중 T4에 가장 근접** | 정면 댄스 위주 학습, 극단 각도 미검증(하지만 4개 중 준비된 도구는 가장 나음) |
| [참고] Wan2.2-Animate-14B (2025 최신) | 있음 | Apache-2.0 | 리타게팅 전처리 4단계 필요(yolov10m+vitpose+SAM2+FLUX) | **불가**(최소 24GB, 형제 14B는 80GB) | 스펙상 무료 Colab과 정면 충돌, 유료 GPU 확보 시 재검토 |

**핵심 발견 — 포즈 포맷 정정**: 처음 계획에 "OpenPose 포맷"이라 썼는데 실제론 MimicMotion·Moore-AnimateAnyone·MusePose 셋 다 **DWPose(RTMPose 기반, COCO-WholeBody 133kpt)**를 씀 — 시각화는 OpenPose와 비슷해 보여도 검출기·키포인트 인덱싱이 다름. 게다가 네 모델 다 기본 파이프라인이 "**실RGB 구동 비디오** → 내부 DWPose 검출 → 스틱피겨 렌더"라서, three.js에서 뽑은 3D→2D 관절 좌표를 쓰려면 검출 단계를 건너뛰고 각 repo의 `draw_pose()` 계열 함수를 직접 호출하도록 스크립트를 고쳐야 함(모델 자체는 그대로 쓰므로 "조립" 원칙은 유지됨, 다만 "설정만 바꾸면 끝"은 아님).

**추천: MusePose 1순위, MimicMotion 2순위.** 이유 — (1) MIT 라이선스로 캡스톤 산출물에 부담 적음, (2) T4 실사용 VRAM(~15GB)에 가장 근접한 문서화 수치, (3) 자체 pose-align 도구가 흔한 실패 요인(레퍼런스-포즈 스케일 불일치) 하나를 미리 없애줌. Champ는 스켈레톤 전용 렌더와 근본적으로 안 맞고, 원본 AnimateAnyone은 코드가 없고, Wan2.2-Animate는 무료 Colab과 스펙이 안 맞아 제외.

**테스트 순서 권장**: 네 모델 다 정면~준정면 학습 데이터 위주라, 처음부터 극단적 탑뷰로 시작하면 실패해도 "우리 구현 문제"와 "모델의 학습 분포 한계"를 구분할 수 없음. **정면 vs 30~45도 회전**처럼 완만한 각도 차이부터 확인한 뒤 극단 각도로 넘어가는 순서 권장.

## 4. 리스크
- **(2026-07-23 확인, 추측 아님)** MusePose·Moore-AnimateAnyone 모두 정면~준정면 댄스 영상 위주로 학습·데모됨 — Moore-AnimateAnyone README가 스스로 "스케일/자세 불일치 시 결과 저하"를 인정. 극단 각도(탑뷰·클로즈업)에서 아티팩트 또는 각도 무시 가능성 실재 — 2절 "테스트 순서 권장" 참고.
- 무료 Colab 세션 제한 때문에 아주 짧은 클립(1~2초)으로만 테스트 가능할 수 있음.
- 포즈 주입 접착 코드(2절 "핵심 발견")가 이번 스파이크에서 가장 시간 걸릴 작업일 가능성 — 사전학습 모델을 그대로 쓰는 "조립"이지만 "설정만 바꾸면 끝"은 아님.
